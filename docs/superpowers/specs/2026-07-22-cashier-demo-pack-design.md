# Дизайн: демо-пакет удобства кассира

Дата: 2026-07-22
Статус: утверждён владельцем (все 5 пунктов)

## Цель

Быстрый видимый апгрейд интерфейса кассы для демонстрации. Только визуал экранов
кассы — без изменений в моделях, сервисах и денежной логике (низкий риск). Первый из
четырёх подпроектов оставшегося UX/контроля (A → B фото → C бэкапы → D отчётность).

## Область (5 пунктов)

1. **Верхняя панель** на всех экранах кассы.
2. **Планшетный экран продажи** (категории-вкладки, плитки товаров, крупная корзина/оплата).
3. **Крупное подтверждение чека** (зелёная плашка + звук).
4. **Быстрые правки чека** (очистить чек, крупные −/+/количество).
5. **Экран ожидания Kaspi** (модальное окно со спиннером, суммой, «Отменить»).

Вне рамок: фото товаров, бэкапы, отчётность (следующие подпроекты); «на исходе» для
кассира (перенесено в подпроект отчётности).

## Компоненты и реализация

### 1. Верхняя панель — новый `app/ui/layout.py`
Функция `cashier_header()`, вызывается первым в теле каждой страницы кассы (`/cashier`,
`/cashier/sale`, `/cashier/refunds`, `/stock/purchase`) после гварда:
- Слева: «☕ Кофейня», имя кассира (`app.storage.user["name"]`), статус смены — читается
  через `shift_service.current_open_shift`: «Смена открыта» (зелёным) или «Смена закрыта».
- Справа: кнопка **«Домой»** → `ui.navigate.to("/cashier")`; кнопка **«Выход»** →
  `guard.logout()` + `ui.navigate.to("/login")`.
- Реализация — `ui.header` (Quasar) с flex-раскладкой, чтобы панель была наверху на всех
  страницах единообразно.

### 2. Планшетный экран продажи — правка `sale_page` в `app/ui/cashier.py`
- Категории — `ui.tabs`/`ui.tab_panels` сверху (вкладка на категорию); активная вкладка
  показывает плитки своих товаров. Заменяет текущий вертикальный список категорий.
- Товары — крупные плитки: `ui.card` в `ui.grid(columns=...)`, крупный шрифт названия и
  цены, высота/ширина под палец (напр. `min-h-28`, широкие). Клик — как сейчас
  (`add_to_cart`).
- Корзина справа — крупнее (шире колонка, крупный шрифт позиций и итога), кнопка
  **«Оплата»** — большая, во всю ширину, заметная.
- Диалоги модификаторов/оплаты — не трогаем логику, только увеличиваем управляющие
  элементы, где уместно.

### 3. Крупное подтверждение + звук — правка `sale_page`
- После успешного `create_sale` (все ветки: наличные/карта/kaspi_qr/kaspi_terminal)
  вместо только `ui.notify` — крупная зелёная плашка (`ui.dialog` с большой галочкой ✓ и
  «Заказ №N проведён», авто-закрытие через ~1.5 сек через `ui.timer(once=True)`), плюс
  короткий звук через `ui.run_javascript` (Web Audio beep — без внешних файлов).
- Вынести в маленький helper в `layout.py`: `sale_success(order_number)`.

### 4. Быстрые правки чека — правка `render_cart` в `sale_page`
- Кнопка **«Очистить чек»** (видна при непустой корзине) → `cart.clear(); render_cart()`.
- Крупные `−`/`+` (увеличить классы), показ количества крупно. Ввод точного количества
  оставляем через `+`/`−` (крупные) — отдельное числовое поле на позицию усложнит вёрстку;
  для демо крупных степперов достаточно. (Числовой ввод — в бэклог, если понадобится.)

### 5. Экран ожидания Kaspi — правка терминальной ветки `confirm_payment`
- Заменить одноразовый `ui.notify("Ожидание оплаты…")` на модальный `ui.dialog`
  (не закрываемый по клику вне) со: спиннером (`ui.spinner`), крупной суммой «К оплате:
  N тг», текстом «Клиент сканирует QR или прикладывает карту», кнопкой **«Отменить»**.
- Оплату запускаем как задачу: `task = asyncio.create_task(kaspi_service.pay(s, total))`;
  «Отменить» вызывает `task.cancel()`. При отмене/`CancelledError` — чек НЕ создаётся,
  модальное закрывается, показывается «Оплата отменена. Если клиент уже оплатил —
  проверьте на терминале». При успехе — модальное закрывается, показывается плашка успеха
  (п.3). Денежный инвариант (чек только при подтверждённой оплате) сохраняется без
  изменений.
- Важно: сессия БД и `create_sale` — как в текущем коде; меняется только «обёртка
  ожидания», не логика проведения.

## Обработка ошибок
- Все существующие ветки ошибок оплаты/чека сохраняются как есть; новое модальное окно
  закрывается в `finally`, кнопка «Провести» остаётся заблокированной на время оплаты
  (уже реализовано).
- `cashier_header()` при отсутствии `app.storage.user` не должен падать (гвард `require_user`
  уже отсекает неавторизованных до вызова хедера).

## Тестирование
Изменения UI-only; по конвенции проекта UI-страницы не покрываются юнит-тестами.
Проверка: полный регресс существующего набора (122 теста должны остаться зелёными,
ничего в сервисах/моделях не меняется) + import-smoke (`import app.ui.cashier`,
`import app.ui.layout`, `create_app(start_bot=False)`), без запуска сервера на порту 8080
(во время разработки на нём уже работает демо-сервер — порт занят). Финальная визуальная
проверка — вручную в браузере владельцем.

## Вне рамок
Фото товаров, резервное копирование, отчётность за период/Excel, X-отчёт, «на исходе» для
кассира, точный числовой ввод количества по позиции — следующие подпроекты/бэклог.
