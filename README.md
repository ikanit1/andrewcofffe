# Coffee POS — касса кофейни

Один Python-процесс: FastAPI + NiceGUI (интерфейс) + aiogram (бот). БД — SQLite.

---

# Установка на чистую машину

Всё делает один файл — `start.ps1`. На пустой машине он развернёт проект с нуля,
на настроенной просто запустит кассу.

## Шаг 1. Поставить Python

Скачайте **Python 3.13** с [python.org](https://www.python.org/downloads/) и при установке
обязательно отметьте галочку **«Add python.exe to PATH»** — без неё скрипт не найдёт Python.

Проверить, что встал:

```powershell
python --version
```

Должно ответить `Python 3.13.x`. Если пишет «не является внутренней или внешней командой» —
галочку не поставили, переустановите.

## Шаг 2. Скачать проект

Либо `git clone`, либо зелёная кнопка **Code → Download ZIP** на GitHub и распаковать.
Путь без кириллицы и пробелов — надёжнее.

## Шаг 3. Завести Telegram-бота

Бот нужен для уведомлений о сменах и возвратах и для ночной отправки бэкапов.
Без него касса работает, но вы ничего не будете видеть с телефона.

1. Напишите **@BotFather** команду `/newbot`
2. Придумайте имя и username бота
3. BotFather выдаст **токен** вида `1234567890:AAE...` — держите под рукой

Токен никому не показывайте: он даёт полный доступ к боту, включая ваши бэкапы базы.
Если засветили — `/revoke` у BotFather, и получите новый.

## Шаг 4. Первый запуск

Правой кнопкой по `start.ps1` → **Run with PowerShell**. Или из терминала:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт создаст окружение, поставит зависимости и спросит две вещи:

- **BOT_TOKEN** — тот самый токен из шага 3 (можно пропустить, Enter)
- **Telegram ID владельца** — ваш числовой идентификатор

**Где взять свой Telegram ID:** напишите `/start` вашему боту. Он вас ещё не знает
и ответит: «Доступ не настроен. Попросите администратора добавить ваш Telegram ID: **123456789**».
Это число и нужно.

Дальше касса откроется в браузере сама.

## Шаг 5. Сменить пин-коды

Заводятся два пользователя с **известными всему миру** пин-кодами:

| Кто | PIN |
|---|---|
| Владелец | `9999` |
| Кассир | `1234` |

Они лежат в `seed.py` в открытом репозитории. Смените оба сразу после входа:
**Админка → Пользователи**. Особенно если планируете публиковать кассу наружу.

# Ежедневный запуск

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт перед стартом проверяет окружение и честно говорит, что не так:

```
=== Coffee POS ===

Окружение:
  [ ok ] Python-окружение на месте
  [ ok ] Зависимости актуальны
  [ ok ] Настройки (.env) прочитаны
  [ ok ] База на месте, пользователей: 2
  [ ok ] Telegram-бот на связи: @имя_бота

Запуск:
  [ ok ] Порт 8080 свободен
```

Telegram проверяется обращением к самому Telegram, а не наличием строки в `.env`, —
если токен протух или это заглушка, вы узнаете до запуска, а не из журнала.

Остановить — **Ctrl+C** в окне.

Флаги:

| Флаг | Что делает |
|---|---|
| `-Funnel` | поднять публичный доступ через Tailscale (см. ниже) |
| `-NoBrowser` | не открывать браузер |

# Доступ с телефона

## В кофейне — по локальной сети

Узнайте адрес моноблока (`ipconfig`, строка IPv4) и заходите с телефона на
`http://192.168.x.x:8080`. Наружу ничего не выставляется.

Может потребоваться один раз разрешить порт 8080 во входящих правилах брандмауэра Windows.

## Отовсюду — Tailscale Funnel

Telegram открывает Mini App только по публичному HTTPS, поэтому кнопка «Открыть кассу»
в боте требует публичного адреса. Tailscale даёт **постоянный** адрес — в отличие от
бесплатного cloudflared, где адрес меняется при каждом запуске и кнопка протухает.

**Что это значит:** касса станет доступна из интернета всем, у кого есть адрес.
Защита — пин-код и лимит попыток (5 подряд, затем минута ожидания). Взвесьте,
нужно ли это, и точно смените дефолтные пины.

1. Поставьте [Tailscale](https://tailscale.com/download/windows) и войдите в свою сеть
2. Запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Funnel
```

3. **Только при самом первом запуске в вашей сети** Tailscale попросит подтвердить
   публикацию по ссылке вида `https://login.tailscale.com/f/funnel?node=...`. Откройте
   и включите. На остальных машинах той же сети подтверждать больше не нужно.

Скрипт сам пропишет выданный адрес в `PUBLIC_URL`. Он будет вида
`https://имя-машины.ваша-сеть.ts.net` и больше не поменяется.

После этого напишите боту `/start` — придёт свежее сообщение с рабочей кнопкой.
Кнопки в старых сообщениях останутся битыми, они хранят прежние адреса.

Выключить публикацию:

```powershell
tailscale funnel --https=443 off
```

Funnel переживает перезагрузку и сам не выключится.

# Автозапуск в кофейне

Когда касса поедет на моноблок и должна подниматься сама при включении:

Правой кнопкой по `install.ps1` → **Run with PowerShell** (согласиться на права
администратора). Он ставит задачи автозапуска: сервер + браузер в режиме киоска
на весь экран.

`install.ps1` использует winget. Если его нет, Python поставьте вручную по шагу 1.

# Обновление

**Узнать, вышла ли новая версия:** в админке раздел **«Версия и обновление»**
(`/admin/about`). Там же видно, какая версия установлена сейчас.

**Обновить:** правой кнопкой по `update.ps1` → **Run with PowerShell**.

Скрипт сам делает копию базы в `backups/`, забирает свежий код, доставляет
зависимости и перезапускает сервер.

**База данных при обновлении не трогается.** `pos.db` лежит в `.gitignore`,
и обновление кода её не перезаписывает: продажи, меню, пользователи, остатки
и настройки Kaspi остаются на месте. То же и с `.env` — токен вводить заново
не придётся.

Если проект скачан архивом (без `git clone`), `update.ps1` это увидит и
подскажет порядок: скачать свежий ZIP и распаковать поверх папки. Данные
не пострадают — ни `pos.db`, ни `.env`, ни `backups` в архиве нет.

Кнопки «обновить» в веб-интерфейсе намеренно нет. Касса доступна из интернета
через Tailscale Funnel, и возможность запустить обновление через браузер была бы
способом выполнить чужой код на моноблоке. Обновление запускается только
с самой машины.

# Работа кассира

1. Войти: выбрать себя, ввести пин-код
2. Открыть смену, указав стартовую наличность
3. Экран продажи: категория → товар → (модификаторы) → корзина → «Оплата»
   (наличные со сдачей, карта или Kaspi; можно разделить оплату на два способа)
4. Возвраты — на отдельном экране: полностью либо частично, с указанием причины
5. В конце — закрыть смену: система покажет ожидаемую наличность, кассир вводит фактическую

Разделы администратора: `/admin/menu`, `/admin/stock`, `/admin/modifiers`, `/admin/users`,
`/admin/dashboard`, `/admin/reports`. Приход товара (`/stock/purchase`) доступен и кассиру.

## Уведомления и сводка дня

Бот присылает: открытие и закрытие смены, инкассацию, возврат, скидку, падение остатка
ниже порога. Уведомления идут через очередь с повторной попыткой — временная
недоступность Telegram их не теряет.

**Итоги дня** приходят автоматически в 22:00 и доступны по команде **`/today`**
(только администратору): чеки, выручка, разбивка по способам оплаты, себестоимость,
маржа и топ товаров.

Сводка считается **по датам, а не по сменам** — забытая незакрытая смена её не искажает.
Наоборот, про такую смену сводка предупреждает отдельной строкой: пока она открыта,
сверка наличности смешивает несколько суток.

Настройки в `.env`: `DAILY_SUMMARY_TIME` (по умолчанию `22:00`), `DAILY_SUMMARY_ENABLED`.

## Отчёты

`/admin/reports` — выручка по способам оплаты, топ товаров, по категориям, себестоимость
и маржа, смены и кассиры. Период — за сегодня, вчера, неделю, месяц или произвольный.
Выгрузка в Excel.

`/admin/dashboard` — выручка и чеки за сегодня, статус смены, позиции на исходе.
Обновляется само.

# Оплата через терминал Kaspi

`/admin/kaspi` (только админ) — адрес терминала, «Проверить связь», «Зарегистрировать кассу».

1. На терминале Smart POS включить «Защита интеграции»
2. В `/admin/kaspi` указать адрес (`https://<ip-терминала>:8080`) и имя кассы,
   нажать «Зарегистрировать кассу», подтвердить на экране терминала
3. На экране продажи выбрать «Kaspi (терминал)» — терминал сам покажет QR или примет
   карту, чек проведётся только после подтверждения оплаты

Терминал ищется в локальной сети кофейни. Если он недоступен, остаётся запасной способ
«Kaspi QR (вручную)» — оплата отмечается кассиром, в отчётах помечена как ручная.

Возврат по терминальной оплате система деньги не возвращает — сделайте это на терминале
вручную, касса об этом предупредит.

# Бэкапы

Каждую ночь (по умолчанию 03:00) создаётся снимок базы в `backups/` и уходит файлом
владельцу в Telegram. Проверить вручную — кнопка **«Сделать бэкап сейчас»** в дашборде.

Настройки в `.env`: `BACKUP_TIME`, `BACKUP_KEEP_DAYS`, `BACKUP_ENABLED`.

## Восстановление

1. Остановить сервер: Ctrl+C, либо `schtasks /End /TN CoffeePOS-Server`
2. Заменить `pos.db` в корне проекта на присланный в Telegram (переименовав в `pos.db`);
   удалить `pos.db-wal` и `pos.db-shm`, если есть
3. Запустить снова

# Если что-то не так

| Симптом | Причина |
|---|---|
| `Python 3.11+ не найден` | не отмечена галочка «Add to PATH» при установке |
| `Порт 8080 уже занят` | касса уже запущена, откройте http://localhost:8080 |
| `Telegram не принял токен` | в `.env` заглушка или отозванный токен — возьмите новый у @BotFather |
| Уведомления не приходят | неверный Telegram ID владельца, проверьте в `/admin/users` |
| Кнопка в боте ведёт в никуда | Funnel не поднят, запустите `.\start.ps1 -Funnel` |
| Кириллица в журнале — каша | старая версия `start.ps1`, обновитесь |
| `Слишком много попыток` | 5 неверных пинов подряд, подождите минуту |

Журнал сервера виден прямо в окне запуска. При автозапуске — в `logs/server.log`.
